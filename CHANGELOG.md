# Changelog

## Unreleased (M1)

- T-30: SDK and editor integration: `@lumpscode/sdk` wraps the core in a plain TypeScript `LumpsClient` that streams a turn with per-chunk callbacks, records provider-reported usage, maps halts to stop reasons, and persists each conversation as a real session, while `lumpscode acp` speaks the Agent Client Protocol over stdio for editor integrations such as Zed with initialize, session/new, streamed session/update chunks, session/cancel, JSON-RPC error handling, and budget halts mapped to max_tokens.
- T-29: distribution: install from npm, a curl installer with checksum and run verification, Homebrew, Scoop, and AUR, plus `lumpscode setup` that writes an owner-only config in one command so a fresh machine reaches its first prompt in seconds; tagged releases build binaries for five platforms in CI, generate the Homebrew formula, Scoop manifest, and PKGBUILD from the real binary hashes, and publish the npm bundle built for plain Node with an external ast-grep native dependency.
- T-28: usage and cost tracking: the agent loop prefers provider-reported token counts over estimates and prices every turn against a built-in model pricing table, so `run` prints real dollars and cache-read tokens reported by OpenAI-compatible and Anthropic streams join the per-conversation aggregate, with the TUI footer showing a live token and cost counter after each turn and `lumpscode update` checking the npm registry for a newer release, while `doctor` now reports the home directory and fails when it is not writable.
- T-27: execution backends: bash now runs through a pluggable backend with local as the default, a docker backend that mounts the workspace at its own path, pins the working directory, disables the network unless explicitly enabled, and supports user and extra docker args, and an ssh backend that runs batch-mode with a quoted remote cd plus port and identity-file options, both reusing the same timeout, abort, and output-cap handling as local execution, selectable through the `execution` config section whose incomplete definitions doctor flags, and verified by routing the bash tool through the docker backend in tests with a stand-in docker binary.
- T-26: messaging gateway: `lumpscode gateway` long-polls the Telegram Bot API and runs incoming tasks on the host, keeping one persisted conversation per chat so context survives restarts, with `/start`, `/help`, and `/new` commands, replies chunked under the Telegram message limit, partial output preserved when a turn fails, and per-chat session mapping stored owner-only; the single-owner trust boundary is enforced by a chat allowlist that tells unknown chats their id for setup, unattended tasks are default-deny behind the same pre-authorization bundle as cron with destructive and secrets rejected at connect time, and the API base is overridable for self-hosted Bot API servers.
- T-25: cron automations: `lumpscode cron add` accepts natural schedules ("every 30 minutes", "every 2 hours", "daily at 09:30", "weekdays at 9am", "every monday at 18:00") or raw five-field cron and rejects nonsense with a typed error, jobs persist owner-only in `cron.json` with the next run computed ahead, `cron start` runs due jobs unattended until interrupted and prints each result, `cron run` executes one now, and `cron list` reports the schedule, next run, and last result with tokens and cost; unattended runs are default-deny: a job may only carry an explicit pre-authorization bundle given at creation, unknown groups are rejected, and destructive and secrets are never pre-authorizable, with the resulting permission surface verified against the unattended check path.
- T-24: session share links: `POST /sessions/:id/share` mints an unguessable token behind the write scope and returns a `/share/<token>` URL, and the public share route renders a self-contained read-only replay of the full session with every message, tool call, and tool result re-redacted at render time so keys that reached memory unredacted never leave the process, markup is escaped to keep transcripts inert, links persist owner-only in `shares.json` so they survive restarts, and unknown or malformed tokens return a plain 404.
- T-23: `lumpscode serve`: a bearer-authenticated HTTP API over the core agent with SSE streaming, scoped tokens where read lists and reads sessions, write creates them, and run drives turns so a read-only token cannot mutate state, sessions persist through the existing store and both the user prompt and streamed assistant reply survive a restart, turns stream as `chunk` events and close with a `done` event carrying halt reason, tokens, and cost, handler failures surface as `error` events while keeping partial output, request cancellation aborts the turn, oversized or invalid bodies are rejected before streaming, and the CLI generates a token when none is provided and shuts down cleanly on SIGINT and SIGTERM.
- T-22: learning loop: a memory curator runs on a turn cadence, extracts facts through the injected model seam, skips facts that already match stored values while updating changed ones, and persists into the project or user tier; auto-skill authoring gates on task complexity (turns plus tool calls), distills the conversational transcript through a summarizer seam into a draft `SKILL.md`, writes it under `.lumpscode/skills/<slug>` without clobbering existing skills, and leaves it in the pending state until one-time human approval through the skills consent flow; cross-session search tokenizes queries, scores user turns above assistant mentions while skipping tool output, returns ranked snippets with dates, and summarizes matches through an optional LLM seam with a rendered digest fallback; a `session_search` tool exposes the same search to agents behind the `read` permission group.
- T-21: web fetch/search and browser control: `web_fetch` validates http/https URLs before the permission check, fetches with a timeout and abort propagation, converts HTML to readable text with the page title and content type, and truncates to a character cap; `web_search` scrapes the DuckDuckGo HTML endpoint, decodes result redirects, and caps results; both tools pass the `network` permission gate with the hostname or query as the audit source and never touch the network when denied; `browser` drives Chrome over the DevTools protocol at `LUMPSCODE_CDP_URL` (default `http://127.0.0.1:9222`) with navigate, snapshot, click, and type actions behind the `browser` permission gate, attaching to an existing page target or creating one, reporting unreachable browsers as `NETWORK_ERROR`, and rejecting non-http navigation before any connection; `mcp add` gains `--preset` with bundled context7, playwright, and serena server definitions, preset-only conflicts and unknown presets are rejected, and the server name defaults to the preset name.
- T-20: checkpoints, rewind, and git worktrees: checkpoints snapshot the workspace into a per-session shadow git repository under the LumpsCode home directory so the user repository is never touched, dependency and build folders stay excluded, duplicate snapshots are skipped, and listing returns labeled checkpoints newest first; rewind restores the exact snapshot state through a throwaway index so modified and deleted files come back, files added after the checkpoint are removed, ignored files and dependency folders survive, and the checkpoint history stays rewindable in both directions; worktree management creates a `lumpscode/<name>` branch at `.lumpscode/worktrees/<name>`, lists porcelain entries, and removes both worktree and branch, with path-traversal names rejected and git failures surfaced as `GIT_OPERATION_FAILED`.
- T-19: four-tier memory: temporary and session tiers stay in process while project and user tiers persist as owner-only JSON under the LumpsCode home directory with atomic writes, project scope is hashed per directory so workspaces never leak entries into each other, and every persisted value is redacted through the shared secret patterns so keys never reach disk while in-memory values stay lossless; per-tier size budgets evict oldest-first and ttl entries expire on read and on reload; a mem0-style extraction pass formats the conversational transcript, skips tool output, dedupes and caps facts, and writes them through `rememberFacts`; retrieval ranks key hits above value hits and returns a top-k set inside a token budget with a `key: value` renderer.
- T-18: context engine: a repo map ranks TypeScript and JavaScript files by import-graph PageRank and renders symbols (`name (kind)` per line) inside a 1k-token budget with a truncation marker, an inverted-index `Context` search scores hits with BM25-lite term weighting plus path boosts, returns the first matching line of each file, and stops at a token budget so ranked file hits stay lean, an `ast_grep` tool adds structural search through ast-grep patterns with language scoping, result caps, and upfront pattern validation, and FR-11 compaction summarizes the middle of a conversation through an injected summarizer, never re-summarizes a previous compaction, clears stale tool results from the summarized span, keeps the most recent turns verbatim, and bounds the generated summary by the reserved headroom; instruction context loads only consented files within a character budget.
- T-17: hooks and plugins: pre-tool, post-tool, session-start, and session-end hooks where a pre-tool decision blocks a call before it runs, hook errors fail closed on pre-tool and stay isolated elsewhere; the tool pipeline emits both events around every execution; plugins are discovered from the user plugins dir and the project `.lumpscode/plugins` dir with manifest validation and path-traversal rejection, user plugins load in-process through an `activate` API while project plugins are untrusted and run out of process over a JSON-lines stdio protocol so they can never patch core, IPC hook calls honor response decisions, time out into a fail-closed block, and load reports name failed plugins with reasons.
- T-16: skills system on the agentskills.io format: `SKILL.md` files parse frontmatter and body, discovery scans project `.lumpscode/skills` and `.agents/skills`, user home, and the bundled pack in precedence order; user and project skills are hash-bound to an approval store and stay pending or rejected as changed until approved, while bundled skills load trusted; progressive disclosure keeps a token-lean catalog and truncates oversized bodies on load; the `skill` tool lists and loads skills behind the `skills` permission gate and the default bundle ships systematic-debugging, verification-before-completion, test-driven-development, and humanizer.
- T-15: plan mode and subagents: built-in `build`, `plan`, and `general` agent definitions carry per-agent tool allowlists and `toolsForAgent` filters the registry so the plan agent cannot reach write, edit, or patch at all while its bash runs behind a `shell` permission check, read-only agents stay write-free by construction; `Subagents` runs research agents on a budgeted `AgentLoop` with depth and concurrency limits, upfront and mid-run cancellation propagation, and compressed results that keep head and tail within a token budget; a `task` tool exposes delegation through the `subagent` permission gate; the TUI Tab switch hands the selected agent to the turn and `@general` routes input to the subagent seam.
- T-14: MCP client on `@modelcontextprotocol/sdk` and `mcp` commands: connects to MCP servers over stdio (spawned process with args and environment) and streamable HTTP (session ids, custom headers, JSON or SSE responses) with a 15s request timeout; lists and calls tools with stringified content normalization, JSON-RPC errors and `isError` results surface as `MCP_TOOL_FAILED` and connection failures as `MCP_CONNECTION_FAILED`; MCP tools register into the tool registry as `mcp_<server>_<tool>` with a coerced JSON schema and every call passes the `external-services` permission gate, so ask-mode flows deny by default; `mcpServers` joins the config schema with project overrides and validation coverage, and `lumpscode mcp list/add/remove/call` manages servers with `--yes` covering the ask-mode confirmation.
- T-13: LSP client: stdio JSON-RPC transport with content-length framing, lazy start with an initialize handshake and capability detection, per-file `didOpen` with language ids inferred from extensions, go-to-definition, references, document symbols with flattened children, and hover normalization, all at 1-based positions with workspace-relative result paths; graceful degradation records a reason and returns empty results when no server is configured, the spawn fails, initialization fails, or the server lacks the capability; an `lsp` tool exposes symbols, definition, references, and hover in a token-lean `file:line:column kind name` format.
- T-12: non-interactive run mode: `lumpscode run "task"` streams the agent answer as plain text and closes with a model, token, and cost summary plus halt reasons, `--verify` captures a test baseline before the task, reruns the detected test command afterwards, and exits nonzero only when failures appear beyond the pre-existing baseline, fixed tests are reported separately, failures parse from vitest, bun, jest, and pytest style output with ANSI stripping and timing normalization so reruns compare cleanly, and the test command is detected from `package.json` scripts with the package manager inferred from the lockfile.
- T-11: session persistence and resume: sessions persist as JSON files under the LumpsCode home directory with owner-only permissions and atomic writes through a temp file rename, every message and tool payload is redacted before it reaches disk while in-memory sessions keep the original text, a fresh store instance reloads a session with timestamps, tool calls, and tool results intact, listing returns metadata newest first and skips corrupt files, resume renders the same context through a shared renderer, and path-unsafe ids are rejected before touching the filesystem.
- T-10: Ink/React terminal UI: transcript with glyph rows (`>` user, `●` agent turn, `⎿` tool result, `»` note), token streaming rendered per chunk, multiline input where enter submits and ctrl+j inserts a newline, cursor editing with arrows, home, end, backspace, and delete, slash palette with prefix filtering and tab completion (`/help` `/clear` `/theme` `/model` `/skill` `/session` `/share` `/exit`), tab toggles between plan and build agents, escape and ctrl+c abort the running turn and mark it interrupted, dark and light themes, emoji-free chrome guarded by a test, snapshot coverage for the main screen, and a first-frame render budget test under 100 ms. Measured cold start of the compiled form is around 0.5 s on the development box where a bare Bun boot alone costs about 100 ms and yoga WASM instantiation inside Ink dominates the remainder; `bun build --compile` needs `react-devtools-core` stubbed (Ink's optional devtools dependency, aliased through a build plugin) and the stub belongs in the T-12 build script.
- T-09: permission engine: destructive and secrets always require explicit user confirmation and are never covered by allow mode, allowedGroups, or unattended pre-authorization bundles; ask-mode misses surface requiresConfirmation; parallel audit log records every decision with redacted sources and reasons, persisted as JSONL through a file sink; shared redaction utility for API keys, tokens, bearer headers, JWTs, and sensitive key-value pairs.
- T-08: core tools: read (line ranges, byte caps, SHA-256), write (directory creation, created flag), edit (unique-fragment replacement with replaceAll), bash (timeout kill, abort cancellation, stream caps, exit codes), glob (recursive walk, workspace scoping, limits), grep (regex, include globs, binary skip, result caps), and patch (rejected with PATCH_CONFLICT when the file no longer matches the expected SHA-256); all file tools resolve paths inside the workspace.
- T-07: tool framework: registry with duplicate-registration warnings, JSON-schema tool definitions, and an execution pipeline that logs every registration, call, completion, and failure with latency, maps errors to the LumpsError taxonomy, honors pre-aborted contexts, and exposes tool specs for provider function calling.
- T-06: agent loop with budgets, bounded iterations, cancellation, and streaming: mid-stream token and duration budget halting with halt reasons, iteration caps checked before each provider call, abort-signal cancellation mapped to a CANCELLED error code, streamed token passthrough, and per-turn usage accounting wired to the usage recorder.
- T-05: Anthropic, Ollama, OpenRouter, and Z.ai adapters with capability metadata: Anthropic messages API with SSE events, Ollama `/api/chat` NDJSON streaming and `/api/tags` catalog, OpenRouter/Z.ai via the OpenAI-compatible adapter with attribution headers, per-provider capability defaults, model-id capability heuristics, and a shared contract test suite across all adapters.
- T-04: provider abstraction and OpenAI-compatible adapter: ModelInfo catalog with capabilities, complete and streamComplete with SSE parsing, models endpoint fetch with catalog fallback, model hot-swap, and config-based adapter instantiation.
